# EduMatch高校专业分析插件：2026.3

当前主入口为`university_analyze`（MCP）或`scripts/university_analysis.py`（CLI）。高校专业是唯一主体，个人访谈不再进入本案例。

## 调用AI的工作顺序

1. 读取主办方四任务与提交规范，固定学校、专业版本、市场时间地域；高校直接提交和公开资料整理必须区别登记。
2. 读取冻结数据和文献原文，检查版本、去重口径、课程身份冲突。已知事实、待核事实和情景假设分别存储。工具名不直接当完整任务。
3. 生成`brief`：`subject=university_program`，含`request`、六任务或其他有据任务框架、证据核读、约束、候选、方向/分流、招生反馈、验证设计、动作风险。
4. 先运行诊断，再提出候选。候选必须引用原文定位，写明目标、活动、考核、学分学时、适用年份、先修状态与资源。
5. 调用课程评价工具。遇硬约束错误不得接受；缺资源/版本/映射证据保持条件。修订引用父方案、工具错误和修改原因。禁止编造失败经历或成功率。
6. 运行高校入口，导出网页及过程。候选由调用AI显式提供，CLI重放不冒充自动调用大模型。若以后接入模型，须另记录模型、参数、实际调用与返回内容。
7. 用实际产物组织PDF五部分与PPT“数据说明+四任务”。网页仅为演示成果，不能替代主办方规定材料。

## 运行

```powershell
python scripts/university_analysis.py --input data/university_cases/BJUT_IM_2024.json --output runs/imis_new
python -m mcp_servers.server --group university
```

输出已有内容时拒绝覆盖。每次新运行保留输入、完整结果、候选评价、哈希链接日志、网页和文件校验清单。网页支持分章节跳转、三情景切换、查看依据和打开结果JSON。可离线打开`index.html`。

本地信管输入由当前Agent依据既有资料生成；`scripts/build_university_case.py`为本案例构造脚本，需本地证据审查文件和授权数据。它不是任意学校的自动采集器。更换学校应准备同字段任务包及数据，补齐适用课程规则，不能只换名称。

## 已知边界

- 本案例未要求个人与AI对话，没有构造个人模拟记录。
- 学校输入来自公开资料整理，不宣称高校直接委托、教师审议或已实施。
- 2024进程表与2020大纲有版本差异；教学覆盖与真实效果未知。
- 三情景包括招生控制与课程资源压力；假设容量、阈值和系数不是文献给定最优值。
- C1被拒绝，C2条件通过。C2不等于已批准，原课总学时不变也不能自动证明教育合理。
- 比较C1与C2的资源减少，必须标明参考对象是被拒绝初稿，不能写成相对现行培养方案的真实节约。
- 已发布2026.2公开仓库与本地2026.3升级须分别标识；未经发布不得声称线上已同步。
